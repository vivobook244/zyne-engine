## 1. Goal

Provide the first desktop window through the platform boundary, with backend-independent configuration and window events. The first vertical slice is a single-window application that opens, receives basic OS window events, and exits cleanly when close is requested.

This phase does not initialize a GPU or renderer. Runtime engine lifecycle orchestration and frame scheduling remain later Phase 1 work.

## 2. Backend

- Selected backend: `winit 0.30.13`.
- Keep backend implementation private to `zyne-platform`.
- Use `ApplicationHandler` and `EventLoop::run_app`.
- Create the native window from `resumed` using `ActiveEventLoop::create_window`.
- Preserve default backend features for Windows and Linux X11/Wayland.
- The event loop must be created and run on the platform-required main thread, once per process.

## 3. Public platform API

Initial API surface:

- `WindowConfig`: title, logical initial size, optional min/max size, resizable, visible, and initial window mode.
- `WindowSize`: dimensions with explicit logical/physical semantics.
- `PlatformWindow`: safe wrapper for common window operations; no public winit types.
- `WindowEvent`: resize, focus, scale-factor, close-request, and redraw notifications.
- `WindowEventHandler`: application callback boundary.
- `WindowControl`: continue or request event-loop exit.
- `WindowRunner`: single-window runner and event-loop owner.
- `PlatformError`: typed configuration, event-loop, window-creation, and handler failures.

The first implementation supports one window. Multi-window identity/management is deferred until there is a concrete use case.

## 5. Manual smoke test

After updating the lockfile and building on a machine with a graphical desktop session:

```bash
cargo run --locked -p zyne-platform --example window_smoke
```

Expected behavior:

1. A 1280×720 logical-pixel window titled `ZYNE — Window Smoke Test` appears.
2. The terminal prints the created window's physical size and scale factor.
3. Resizing, focusing, changing display scale, and redraw requests are reported where generated by the OS.
4. Closing the window exits the event loop normally.

Do not run this example in a headless CI job without a configured display server.

## 8. Known implementation constraints

- Winit 0.30 requires window creation during an active event-loop callback. The runner creates the window in `resumed`.
- Event-loop creation has platform-specific main-thread and single-instance requirements. Call the runner from the application main thread.
- Window size configuration is logical pixels; resize event dimensions and `PlatformWindow::inner_size` are physical pixels. The scale-factor event allows consumers to relate them.
- A window callback runs on the event-loop thread and must not block.
- A headless CI environment can compile and test configuration, but cannot prove that a native desktop window displays correctly.
